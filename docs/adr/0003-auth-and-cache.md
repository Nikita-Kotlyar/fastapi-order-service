# ADR 0003: JWT + RBAC в PostgreSQL и Redis-кэш с fallback

## Status

Accepted.

## Context

Сервис используется аналитиками, операторами и администраторами. Нужны
разграничение прав, короткоживущие access-токены и возможность отзыва
пользователя без перезапуска приложения. Read-heavy API требует кэша, но
сервис должен оставаться работоспособным при недоступном Redis.

## Decision

- Пользователи и роли хранятся в PostgreSQL (`users`).
- Пароли — PBKDF2-SHA256 с индивидуальной солью.
- Access JWT живёт 60 минут, refresh JWT — 7 дней; тип токена проверяется.
- Роли проверяются по актуальной записи пользователя, а не только по claims.
- Кэш использует Redis при наличии `ORDERHUB_REDIS_URL`, иначе in-memory TTL.
- Любая запись инвалидирует namespace `orderhub:*`.
- Ответы list/detail содержат `X-Cache: HIT|MISS`; счётчики видны в `/metrics`.

## Consequences

- Деактивация пользователя действует на следующем запросе.
- Redis не является единственной точкой отказа.
- Нет token revocation и rotation refresh-токенов; это следующий шаг.
- In-memory fallback не разделяется между репликами; для multi-instance
  обязателен Redis.
